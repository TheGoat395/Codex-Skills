# Content Structure Information Architecture Guide

## Lens

Good visual design cannot rescue a confusing information path.

## Rules

- Identify primary users and their top questions.
- Map pages and sections around tasks, proof, and action.
- Use navigation labels that match user intent.
- Decide what belongs on the homepage versus deeper pages.

## Useful Patterns

- Product: overview, use cases, features, integrations, pricing, docs.
- Service: offer, who it is for, process, proof, packages, inquiry.
- Portfolio: selected work, case studies, about, contact.
- Commerce: collection, product detail, story, reviews/proof, checkout.

## Avoid

- Adding sections because templates usually have them.
- Hiding the primary action.
- Using clever nav labels that obscure purpose.

## Acceptance Criteria

- The site answers user questions in a natural order.
- Navigation and section names are clear.

## Scoped execution

Apply [the shared web contract](../../website-operating-rules/references/scoped-web-contract.md) to the requested surface. Preserve this guide's specialist rules; reuse existing context and evidence. Analysis stays read-only, and extra polish/checks follow an actual defect or changed behavior, not a pass count.
