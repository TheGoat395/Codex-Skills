# Conversion Forms Checkout Polish Guide

## Lens

A premium site still needs the user to act. Conversion design should feel calm, specific, and complete.

## Rules

- Match CTA language to the action and context.
- Design empty, focus, filled, error, disabled, and loading states.
- Use trust details close to action: cancellation, response time, privacy, availability, payment, shipping, support.
- Keep forms short unless complexity is necessary.

## Useful Patterns

- Service inquiry: name, email, project type, budget/range, message.
- Booking: offer, date/time, contact, confirmation state.
- Checkout: product summary, price clarity, shipping/returns, payment confidence.
- Pricing: table or concise plan comparison, not default card trio.

## Avoid

- Unstyled forms on polished pages.
- Generic Submit button.
- Pricing cards without real differences.

## Acceptance Criteria

- A user knows what happens after clicking.
- The flow has credible states and mobile polish.

## Scoped execution

Apply [the shared web contract](../../website-operating-rules/references/scoped-web-contract.md) to the requested surface. Preserve this guide's specialist rules; reuse existing context and evidence. Analysis stays read-only, and extra polish/checks follow an actual defect or changed behavior, not a pass count.
