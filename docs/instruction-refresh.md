# Instruction delivery refresh

The active catalog keeps the existing capabilities while shortening discovery descriptions, moving conditional detail behind explicit references, reducing repeated operating rules and aligning tests and approval boundaries with the requested task. Repaired evidence helpers distinguish structural records from actual observations, reject missing or false evidence, and preserve recovery during migrations and artifact writes.

The refresh includes relevant earlier routing, evidence-loop and native View Transition work. It does not add a forced model hierarchy or change host configuration. Select focused collections; installed skills are available guidance rather than an instruction to load every workflow.

## Evidence and limits

Repository checks validate metadata, collections, installation dry runs, Python syntax, reference integrity and representative helper regressions. These are not a matched model benchmark or a claim of universal quality, latency or token savings. Earlier published benchmarks retain their original dates and limitations.

## Recovery

The change is versioned on a dedicated branch and can be reverted through Git. Installer replacement backups remain explicit. A public export contains only the curated public collection; personal runtime configuration, account memory, local audit paths and proprietary plugin caches are outside its scope.

## Verified repository checks

The catalog validates at 80 active skills. Ten focused regressions cover short and blank descriptions, name mismatch, cache-free inventories, installer dry-run behavior, successful replacement, staging failure, backup collisions, activation rollback and symlink-target refusal. Python syntax and relative Markdown references were checked. These results use disposable local fixtures, with no model or production execution.
